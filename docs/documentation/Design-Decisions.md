# Design Decisions

## Architecture Overview
ClassSaga was built as a full-stack MERN web application (MongoDB, Express, React, Node.js). The application follows a standard client-server architecture that separates frontend logic, backend logic, and data management. MongoDB was chosen as the database due to its flexible document model which allows for game entities to easily evolve over time and as the application scales. React was chosen for the frontend due to its component-based architecture which suited a UI with many different interfaces and states. Express and Node.js were used to create a RESTful API layer that is responsible for server-side management. JWT authentication was utilized to manage user sessions securely and provide role based access. 

## Data Model Decisions
ClassSaga's data model was designed around the core systems of the application: users, pets, items, and inventory. While students and teachers share a User model, there is an important role field to differentiate behavior and access. Classrooms reference a teacher and a list of enrolled students in order for the teacher to manage student membership and classroom data. Pets are modeled separately from users to allow for multiple owned pets. The pets have an isActive field to switch between pets and also have distinct care stats and battle stats for daily engagement and progression. Shop items are modeled separately from inventory items in order to define what can be purchased. Inventory tracks what the student actually owns and reference the shop items which allows for easier updates and reduces redundancy. Equipment is also a separate model from inventory to allow cosmetic items to be equipped and persistent on multiple pets. Point transactions are stored as separate records to preserve a history of awarded and spent points. Daily care actions are also tracked separately from pets so that students can use exactly one free feed, play, and brush action per day.

## Game Design Decisions
ClassSaga was designed around a positive reinforcement loop where academic participation results in points that can be immediately spent on rewarding in-game interactions. This was meant to create a clear connection between classroom behavior and progression. However, the game systems were intentionally designed to be lightweight so that the app can be used to enhance classroom engagement without becoming a distraction that consumes a lot of time. A virtual pet was chosen as the central mechanic because of the potential for attachment, routine interaction, and personalization options which encourage students to care for and stay engaged with their pet over time. Daily interactions intentionally keep sessions short while also creating a natural idle progression loop. A level-up and stat increase system was added as a way to provide this long-term progression to maintain student engagement and provide a continuous sense of achievement and growth. This also encourages students to care for their pet for the benefits it provides. The point-based economy was introduced to make rewards feel meaningful and to provide student autonomy in how they want to spend their resources. Customization was prioritized through cosmetics, single-use items, and multiple pets which helps to increase investment in the system. A basic NPC battle system was added as an additional daily engagement mechanic and to give purpose to progressing a pet's level and stats. 

## Educational Design Decisions
ClassSaga was designed with specific educational priciples in mind which guided a lot of features and decision making. The app is built around positive reinforcement where students are rewarded for desired behaviors. It does not use negative reinforcement in any way as there is no penalization of students. Teachers currently have full control over point distribution which helps to ensure that the system is supporting classroom goals. Ensuring that sessions on the app are short and intentional was a very important consideration so that instructional time is not interrupted. The app is meant to supplement the classroom experience and increase student motivation rather than compete with it for student attention. The decision to center the app around a virtual pet also supports important skills for students like responsibility, resource management, and delayed gratification in a low-stakes context.
